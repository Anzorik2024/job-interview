Шпаргалка для собеседований (Frontend)

Семантический HTML — использование тегов, отражающих смысл содержимого: <header>, <article>, <nav> и т. д. Преимущества:

  • Улучшение доступности (для скринридеров)
  • Лучшая SEO-оптимизация
  • Упрощение поддержки кода

Flexbox — одномерная система раскладки (строка или столбец). Идеален для выравнивания элементов внутри контейнера.

Grid — двумерная система (строки и столбцы одновременно). Подходит для создания макетов страниц.

Event loop — механизм, позволяющий JS выполнять асинхронный код без блокировки основного потока. Этапы:

  1. Выполнение синхронного кода
  2. Помещение асинхронных задач в очередь (callback queue)
  3. Обработка событий из очереди, когда стек вызовов пуст

Типы данных:

  1. undefined — самостоятельный тип "undefined"
  2. null — исторически считается объектом (typeof null === "object"), хотя технически это отдельный тип. Это признанный баг языка.

Как они возникают:

undefined — значение, которое JavaScript присваивает автоматически:

  1. Объявленная, но не инициализированная переменная.
  2. Доступ к несуществующему свойству объекта.
  3. Параметр функции, для которого не передан аргумент.
  4. void 0 (часто используется как безопасный способ получить undefined).

    5. null — всегда задаётся программистом вручную, чтобы указать «здесь намеренно ничего нет».

Сравнение:

  1. null == undefined // true (нестрогое равенство)
  2. null === undefined // false (строгое равенство, разные типы)

Преобразование в числа:

  1. Number(null) // 0
  2. Number(undefined) // NaN
  3. null + 5 // 5
  4. undefined + 5 // NaN

В булевом контексте:

  1. !!null // false
  2. !!undefined // false

В JSON:

  • null — корректное JSON-значение: JSON.stringify({a: null}) → '{"a":null}'.
  • undefined — игнорируется (или превращается в null при замене): JSON.stringify({a: undefined}) → '{}'.

    • Оператор in и проверка свойств:

    let obj = { a: undefined, b: null };

    1. console.log('a' in obj); // true (свойство есть)
    2. console.log('b' in obj); // true
    3. console.log('c' in obj); // false

    Идиомы и рекомендации:

    1. Проверка на «пустоту» часто пишется как if (value == null) — ловит и null, и undefined.
    2. Для строгой проверки: if (value === undefined) или if (value === null).
    3. Если переменная должна явно обозначать «нет значения», обычно используют null. undefined оставляют для системных ситуаций.

    Область видимости

    1. var: доступна внутри всей функции, даже если объявлена внутри блока (if, for). Вне функций становится глобальной.

      if (true) { var a = 10; } console.log(a); // 10 (утечка из блока)

    2. let и const: видны только внутри блока { ... } (цикл, условие, функция и т.д.).
      if (true) { let b = 20; } console.log(b); // ReferenceError

    Поднятие (hoisting) и временная мёртвая зона (TDZ)

    1. var: поднимается, но инициализируется undefined. К ней можно обратиться до объявления – получите undefined.

      console.log(x); // undefined var x = 5;

    2. let / const: тоже поднимаются, но не инициализируются. До фактического объявления переменная находится в «временной мёртвой зоне» (Temporal Dead Zone). Доступ к ней вызывает ReferenceError.

      console.log(y); // ReferenceError: Cannot access 'y' before initialization let y = 5;

    Повторное объявление

    1. var c = 1; var c = 2; // OK
    2. let d = 1; let d = 2; // SyntaxError
    3. const e = 1; const e = 2; // SyntaxError

    Изменение значения

    1. var / let: можно менять сколько угодно раз.

    2. const: нельзя переприсвоить переменную. Однако если это объект или массив, можно изменять его содержимое (свойства, элементы).

      const user = { name: "John" }; user.name = "Jane"; // OK user = {}; // TypeError: Assignment to constant variable

    Инициализация

    1. var v; // OK, значение undefined
    2. let l; // OK, значение undefined
    3. const c; // SyntaxError: Missing initializer in const declaration

    Что использовать?

    1. const по умолчанию (если значение не будет переназначаться).
    2. let когда переменная должна меняться (счётчики, аккумуляторы).
    3. var лучше избегать в современном коде из-за неочевидного поведения с областью видимости и утечек в глобальный объект.

    Как включить

    Достаточно добавить строку 'use strict'; (или "use strict";) в начало скрипта или функции.

    javascript 'use strict'; // весь код в этом файле работает в строгом режиме

    Что меняет строгий режим:

    1. Запрет на неявное создание глобальных переменных

      В обычном режиме присвоение значения необъявленной переменной автоматически создаёт глобальную переменную. В строгом режиме это вызывает ошибку.

      javascript 'use strict'; x = 10; // ReferenceError: x is not defined

    2. Невозможно удалить переменные, функции или параметры

      delete для идентификатора (переменной или функции) запрещён.

      javascript 'use strict'; let a = 5; delete a; // SyntaxError: Delete of an unqualified identifier ...

    3. Одинаковые имена параметров функции

      В обычном режиме разрешено дублирование имён параметров. В строгом — ошибка синтаксиса.

      javascript 'use strict'; function sum(a, a, c) { // SyntaxError: Duplicate parameter name not allowed return a + a + c; }

    4. Упрощение this в функциях

      Глобальные функции получают this равный undefined, а не объект окна (в браузере window). Это предотвращает случайное создание глобальных свойств через this.

      javascript 'use strict'; function show() { console.log(this); // undefined } show();

    5. Запрет на использование with

      Конструкция with полностью запрещена, так как делает код неоптимизируемым и непредсказуемым.

      javascript 'use strict'; with (Math) { // SyntaxError: Strict mode code may not include a with statement x = cos(2); }

    6. Запрещены восьмеричные литералы (прежний синтаксис)

      Восьмеричные числа с ведущим нулем больше не разрешены (но 0o-префикс работает).

      javascript 'use strict'; let num = 012; // SyntaxError: Octal literals are not allowed in strict mode.
      let oct = 0o12; // ОК, современный синтаксис

    7. Ошибки при попытке записи в readonly-свойства, добавления свойства в нерасширяемом объекте и т.п.

      Раньше такие действия молча игнорировались, теперь бросают исключение.

      javascript 'use strict'; let obj = {}; Object.defineProperty(obj, 'x', { value: 42, writable: false }); obj.x = 100; // TypeError: Cannot assign to read only property 'x'

    8. Ограничения на eval и arguments

      eval не может вводить новые переменные во внешнюю область видимости (работает в своей собственной области).

      arguments ведёт себя как обычный идентификатор, его нельзя переопределить и он не синхронизируется с параметрами функции.

      javascript
      'use strict';
      function f(a) { arguments[0] = 10; // изменяет только arguments, а не параметр a console.log(a); // старое значение (не 10) }

    9. Запрет на использование зарезервированных слов в качестве имён переменных

      Слова, зарезервированные для будущих версий (implements, interface, let, package, private, protected, public, static, yield), нельзя использовать как имена переменных.

      javascript
      'use strict';
      let private = 5; // SyntaxError: Unexpected strict mode reserved word

    10. function внутри блока ведёт себя по правилам ES6 (ограниченная область видимости)

      В строгом режиме объявление функции внутри блока (if, for и т.д.) будет видно только внутри этого блока, а не подниматься в родительскую функцию.

    Преимущества использования строгого режима

    1. Безопасность – устраняет случайное создание глобальных переменных.

    2. Понятность – запрещает сомнительные конструкции (with, eval в глобальной области и др.).

    3. Производительность – некоторые оптимизации компилятора становятся возможны благодаря более предсказуемому поведению.

    4. Совместимость с будущим – запрещает использование зарезервированных слов, которые могут появиться в следующих версиях JS.

    Когда строгий режим включён автоматически

    1. Модули (ES6 modules) – весь код внутри модуля по умолчанию работает в строгом режиме.

    2. Классы (ES6 classes) – тело класса и его методы выполняются в строгом режиме.

      javascript class Example { someMethod() { // здесь уже строгий режим x = 10; // ReferenceError } }

    3. Стрелочные функции – если они объявлены в строгом окружении.

    Рекомендация

    Всегда используйте строгий режим. В новых проектах, основанных на модулях или классах, он уже включён автоматически. Для старых скриптов, которые не используют модули, добавьте 'use strict' в начале файла.

    Пример сравнения

    Обычный режим (слабый)

    javascript function test() { x = 5; // создаётся глобальная переменная x delete x; // молчаливо игнорируется (или false) console.log(x); // 5 } test();

    Строгий режим

    javascript 'use strict'; function test() { x = 5; // ReferenceError delete x; // до ошибки не доходит } test();

    В JavaScript данные делятся на примитивные (простые) типы и ссылочный тип (объекты). Вот полный список:

      Примитивные типы (7 штук)

    1. number — целые и дробные числа, также специальные значения Infinity, -Infinity, NaN (Not a Number).
    2. bigint — целые числа произвольной точности (появился в ES2020). Создаётся добавлением n в конце: 123n.
    3. string — текстовые строки (можно в одинарных, двойных или обратных кавычках).
    4. boolean — логические значения: true и false.
    5. undefined — значение «не назначено». У переменной, которая объявлена, но не инициализирована.
    6. null — значение «пусто» или «объекта не существует».
    7. symbol (ES2015) — уникальные и неизменяемые идентификаторы, часто для ключей свойств объекта.

    Ссылочный тип

      object — сложные структуры данных. Сюда входят:

    1. обычные объекты {...}
    2. массивы [...]
    3. функции
    4. даты (Date)
    5. регулярные выражения (RegExp)
    6. и другие встроенные объекты (Map, Set, WeakMap и т.д.)

    Особенности:

    1. Примитивы хранятся и копируются «по значению».
    2. Объекты — «по ссылке».
    3. Оператор typeof помогает определить тип, но есть нюансы:
      • typeof null → "object" (это исторически сложившийся баг языка)
      • typeof function(){} → "function" (хотя функция — подвид объекта).

    Строки в JavaScript неизменяемы (immutable). Это значит, что вы не можете изменить существующую строку — любая операция, которая кажется добавлением символа в конец строки, на самом деле создаёт новую строку.

    let str = "Hello";
    str += "!"; // создаётся новая строка "Hello!", а не изменяется старая

    Старая строка "Hello" остаётся в памяти до тех пор, пока на неё есть ссылки, или пока сборщик мусора её не удалит. Сама операция конкатенации всегда порождает новый строковый объект.

    Анонимная функция в JavaScript — это функция, у которой нет имени. Она используется там, где нужно передать функцию как значение, но не требуется её идентификация по имени.

    Примеры анонимных функций

    1. Function Expression (присваивание переменной):

      const greet = function() { console.log("Привет!"); };
       greet(); // "Привет!"

    2. Стрелочные функции (всегда анонимны):

      const sum = (a, b) => a + b;

    3. Колбэки (передача функции в другую функцию):

      setTimeout(function() { console.log("Прошла секунда"); }, 1000);

    4. Немедленно вызываемая функция (IIFE):

      (function() { console.log("Выполнилась сразу"); })();

    Почему они нужны?

    1. Удобно передавать функцию «на лету» как аргумент.
    2. Не засоряют глобальную область видимости.
    3. Позволяют создавать замыкания.

    Важное отличие

    У анонимной функции нет имени, поэтому её сложнее отлаживать. Но стрелочные функции и современные инструменты частично решают эту проблему.

    1. Hoisting (всплытие)

    Hoisting — это механизм JavaScript, при котором объявления переменных и функций поднимаются в начало своей области видимости (скоупа) перед выполнением кода. Однако важно различать, что именно поднимается и как ведут себя разные типы объявлений.

    Переменные:

    1.  var — объявление поднимается, но инициализация остаётся на месте. До инициализации переменная существует, но имеет значение undefined.

      Пример hoisting с var:

      console.log(a); // undefined (не ошибка!)
      var a = 5;
      console.log(a); // 5
      // Как это видит движок:
      // var a;
      // console.log(a); // undefined
      // a = 5;
      // console.log(a); // 5

    2. let и const — тоже поднимаются, но находятся во «временной мёртвой зоне» (TDZ) до момента объявления. Доступ к ним до строки объявления вызывает ошибку ReferenceError.

      Пример с let:

      console.log(b); // ReferenceError: Cannot access 'b' before initialization
      let b = 10;

    Функции:

    1. Function Declaration (объявление функции) — поднимается полностью (и объявление, и тело), поэтому функцию можно вызывать до её определения в коде.

      sayHello(); // "Hello!" — работает, потому что функция поднята целиком
      function sayHello()
      { console.log("Hello!"); }
    2. Function Expression (присваивание функции переменной) - — подчиняется правилам переменной (см. var, let, const).

    2. Замыкание (closure)

    Замыкание — это функция, которая «запоминает» своё лексическое окружение (переменные из внешней функции) даже после того, как внешняя функция завершила выполнение. Другими словами, внутренняя функция имеет доступ к переменным внешней функции, даже когда вызывается за пределами внешней.

    Как работает замыкание:

    1. Каждая функция в JavaScript создаёт свой лексический скоуп.
    2. Если внутренняя функция ссылается на переменные внешней, то эти переменные не удаляются сборщиком мусора, пока существует внутренняя функция.

    Основные применения замыканий:

    1. Создание приватных переменных.

    2. Фабрики функций (например, счётчики).

      Простой счётчик:

      function createCounter() {
      let count = 0; // переменная внешней функции
      return function() {
      count++; // внутренняя функция «замыкает»
      count return count;
      };
      }
      const counter = createCounter();
      console.log(counter()); // 1
      console.log(counter()); // 2
      console.log(counter()); // 3
      // Переменная count не доступна напрямую:
      console.log(count); // ReferenceError: count is not defined
    3. Каррирование и частичное применение.
    4. Обработчики событий, сохраняющие состояние.

    Итог

    1. Hoisting — это «поднятие» объявлений в начало скоупа, позволяющее использовать функции и переменные (var) до их фактического объявления (но с осторожностью).
    2. Замыкание — это способность функции помнить своё лексическое окружение, даже когда выполнение выходит за пределы этого окружения. Это мощный инструмент для создания гибкого и модульного кода.

    Основное различие между Function Declaration (объявление функции) и Function Expression (функциональное выражение) в JavaScript — в том, как интерпретатор обрабатывает их во время выполнения кода. Вот ключевые отличия:

    1. Поднятие (Hoisting)

      • Function Declaration полностью поднимается в начало своей области видимости. Функцию можно вызвать до её объявления в коде.

        // Function Declaration
        foo(); // "Привет" - работает
        function foo()
        {
         console.log("Привет");
        }

      • Function Expression поднимается только переменная (var), но не её значение. Поэтому вызвать функцию до её определения нельзя (ошибка TypeError или ReferenceError в зависимости от способа объявления переменной).

        // Function Expression
        bar(); // Ошибка: bar is not a function (или undefined при var)
        var bar = function()
        {
          console.log("Пока");
        }

    2. Имя функции

      • Function Declaration всегда должно иметь имя.

      • Function Expression может быть анонимным (без имени) или именованным. Анонимные функции часто передаются как аргументы или присваиваются переменным.

      javascript
      // Declaration — имя обязательно
      function sum(a, b)
      {
      return a + b;
      }
      // Expression — анонимная
      const multiply = function(a, b) { return a * b; }; // Expression — именованная (имя полезно для рекурсии и отладки)
      const factorial = function fact(n) {
      return n <= 1 ? 1 : n * fact(n - 1);
      };

    3. Где можно использовать

      • Function Declaration допустимо только в основном потоке кода или внутри других функций (нельзя внутри блоков типа if, while, for в строгом режиме — поведение может быть непредсказуемым или вызывать ошибки).

      • Function Expression можно использовать везде, где ожидается выражение: в блоках, в тернарных операторах, как аргументы других функций и т.д.

      // Declaration внутри блока — плохая практика, может не работать в разных браузерах
      if (true) {
      function hello() {
      console.log("Hello");
      }
      // не гарантируется }
      // Expression внутри блока — корректно
      let hello;
      if (true) {
      hello = function() { console.log("Hello"); };
      }

    4. Область видимости

      • Function Declaration имеет блочную область видимости только в строгом режиме (ES6+). В нестрогом режиме может вести себя неинтуитивно. На практике лучше избегать объявления функций внутри блоков.

      • Function Expression подчиняется обычным правилам области видимости переменных (блочной для let/const, функциональной для var).

    5. Завершающая точка с запятой

      • Function Declaration не требует точки с запятой в конце.

      • Function Expression (как часть присваивания или выражения) обычно завершается точкой с запятой.

    6. Когда что использовать?

      • Declaration — когда вам нужна функция, которую можно вызывать до определения, и которая является основной частью модуля/скрипта.

      • Expression — когда нужно передать функцию как колбэк, создать её условно, или ограничить область видимости.

    В JavaScript разница между == и === ключевая и касается приведения типов.

    • == (нестрогое равенство) – сравнивает значения, при необходимости приводя типы к одному. Следует сложным правилам абстрактного равенства (алгоритм Abstract Equality Comparison).

    • === (строгое равенство) – не приводит типы. Возвращает true, только если тип и значение операндов совпадают. Работает по алгоритму Strict Equality Comparison.

    Ключевые отличия на примерах

    1 == '1' // true – строка '1' преобразуется в число 1
    1 === '1' // false – число vs строка
    0 == false // true – false → 0, затем 0 == 0
    0 === false // false – number vs boolean
    null == undefined // true – специальное правило: они равны друг другу через ==
    null === undefined // false – null (object? null) vs undefined
    '' == 0 // true – пустая строка → 0
    '' === 0 // false
    [] == '' // true – массив → пустая строка (через toString)
    [] === '' // false
    NaN == NaN // false – NaN не равно ничему, включая себя
    NaN === NaN // false – аналогично
    // объекты сравниваются по ссылке
    {} == {} // false (разные объекты в памяти)
    {} === {} // false

    Как работает приведение типов в == (упрощённо)

    • Если типы одинаковы – сравниваются так же, как === (но с NaN всё плохо).
    • Если null сравнивается с undefined – true.
    • Если число и строка – строка приводится к числу.
    • Если один операнд булевый – он приводится к числу (true → 1, false → 0).
    • Если объект и примитив – объект приводится к примитиву (чаще всего через toString/valueOf).

    Когда использовать?

    • Практически всегда используйте ===. Это избавляет от неочевидных багов, например:

      if (someValue == 2) {
      // сработает при someValue = '2', что может быть неожиданно
      }

    • Исключения, где == может быть удобен:

      • Проверка на null или undefined:

        if (value == null) – вернёт true и для null, и для undefined (вместо value === null || value === undefined).

      • Чтение с сервера строковых чисел, когда вы точно хотите нестрогого сравнения (но лучше сначала преобразовать явно: Number(value)).

    Итог:
    === безопаснее, предсказуемее и быстрее, так как не тратит время на приведение типов.
    == — источник тонких ошибок, если не знать всех правил.

    В JavaScript у NaN есть особенность: он не равен сам себе. Поэтому простое x === NaN не сработает.

    NaN в JavaScript расшифровывается как "Not a Number" (не число), но это числовой тип (typeof NaN === "number"). Оно обозначает результат математической операции, которая не дала осмысленного числа.

    Когда возникает NaN:

    • 0 / 0
    • Math.sqrt(-1)
    • parseInt("abc")
    • Number("hello")
    • undefined + 1 (или любая операция с undefined, приводящая к числу)
    // Старый способ (с приведением типов)
    isNaN(x); // вернёт true, если x — NaN или нечисловое значение (например, строку "abc")
    // Надёжный способ (без приведения)
    Number.isNaN(x); // true только если x === NaN

    В JavaScript параметры передаются только по значению (pass-by-value). Однако важно понимать разницу для примитивов и объектов.

    Для примитивов (числа, строки, булевы, null, undefined, Symbol, BigInt)

    Передаётся копия значения. Изменение параметра внутри функции не влияет на исходную переменную.

    function changePrimitive(x) {
    x = 10; // меняем локальную копию
    }
    let a = 5;
    changePrimitive(a);
    console.log(a); // 5 – не изменилось

    Для объектов (включая массивы, функции, даты, обычные объекты)
    Передаётся копия ссылки на объект. Сама ссылка передаётся по значению, но через эту копию можно изменять сам объект. При этом если внутри функции присвоить параметру новый объект, внешняя переменная не изменится.

    function modifyObject(obj) {
    obj.name = "new"; // меняет свойство исходного объекта
    }
    let myObj = { name: "old" };
    modifyObject(myObj);
    console.log(myObj.name); // "new" – объект изменился

    function reassignObject(obj) {
    obj = { name: "different" // перезаписывает локальную ссылку
    };
    }
    let anotherObj = { name: "original" };
    reassignObject(anotherObj);
    console.log(anotherObj.name); // "original" – внешняя переменная не изменилась
